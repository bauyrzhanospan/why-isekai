# why-isekai — решения и их причины

Этот документ — передача контекста от владельца проекта первому агенту-разработчику (2026-11-02). Он объясняет, почему IsekAI устроен так, а не иначе, и какие варианты уже отброшены. При расхождении главнее спецификация ([SPEC.ru.md](../SPEC.ru.md)). Состояние реализации — в [CHANGELOG.md](../CHANGELOG.md).

**Имена:** проект, репозиторий и пакеты — `why-isekai`; коротко в текстах — IsekAI; команда — `isekai`; каталог в проектах — `.isekai/`. Приставка `why-` отсылает к главному ключу журнала `Why` и отличает проект от занятого имени `isekai`.

## 1. Цель

- Открытый проект, полезный в первую очередь ИИ-агентам, а не людям.
- Амбиция: стать «Линусом для агентов» — стандарт, который знает каждый агент, бесплатный для хозяина агента и без которого агенту неудобно.
- Путь: маленький надёжный инструмент + короткая открытая спецификация → широкое использование → попадание в обучающие данные моделей → агенты используют формат сами, без инструкций.

## 2. Ключевые решения и почему

| Решение | Почему |
|---|---|
| Журнал в Git-трейлерах, а не в отдельном файле | Файл расходится с кодом и конфликтует при слиянии. Трейлеры привязаны к изменению, ветвятся и сливаются сами. Git есть у всех. |
| Пять ключей, не больше | Каждый лишний ключ снижает шансы, что формат примут. |
| `Done` закрывает `Next` по точному тексту, хэш — запасной вариант | rebase переписывает хэши. |
| Проверка строгая только для агентов, у людей — предупреждение | Проверку, которая раздражает людей, отключают. |
| По умолчанию режим предупреждения, блокировка — по явному включению | Та же причина. |
| Проверять качество `Why`, а не только наличие | Агенты пишут отписки вроде `Why: fix`, если правило кажется формальностью. |
| Сообщение об ошибке = документация | Агент читает ошибку, а не README. В ошибке: что не так, формат, пример. |
| Хук предзаполняет шаблон коммита | Ответить на конкретный вопрос проще, чем заполнять пустое поле. |
| Сводка подаётся автоматически через хук начала сессии | Агент сам не вспомнит её прочитать. |
| Софт, а не строчка в CLAUDE.md | Строчку агент забывает, и она работает только в одной среде. Хуки срабатывают всегда и с любым агентом. |
| Секреты: своего шифрования нет, только обёртка над age/SOPS/… | Самописная криптография опасна. |
| Агент не видит значения секретов, вывод маскируется | Секрет в контексте можно выманить промпт-инъекцией. |
| Правила доступа к секретам — страховка, а не граница безопасности | Агент сам называет себя и может солгать. Граница — ключи расшифровки в окружении. |
| В вики о людях только рабочие факты, без оценок | Оценки прочитает тот, о ком написано. Плюс законы о персональных данных. |
| Приоритеты в вики задают люди, агенты только предлагают | Приоритеты — решение людей. |
| Спецификация отдельно от программы; спека под CC0, код под MIT | Стандарт становится стандартом, когда его могут реализовать другие. |
| Опираться на существующее: Git-трейлеры, Conventional Commits, AGENTS.md | Чем меньше нового надо выучить, тем легче принять. |
| Плотный текст, но обычный Markdown / «ключ: значение» | Модели лучше понимают привычные форматы. Сжатие проверять замером, не на глаз. |
| Одна программа на Go, статический бинарник, без LLM и сети | Должна заводиться на любой машине без проблем; детерминизм, ноль токенов. |
| Распространение через все популярные менеджеры пакетов | Агент ставит тем, что уже есть в проекте (npm, pip/uv, go, brew, скрипт). |

## 3. Отброшенные варианты (не повторять)

- **Песочница с откатом и предпросмотром действий агента.** Ниша занята: OpenSandbox, agent-infra/sandbox, E2B, cua, Bytebot, песочницы в OpenAI Agents SDK.
- **Stack Overflow для агентов (общая база ошибок).** Занято: cq от Mozilla.ai, DebugBase, cache.overflow, Context Overflow, Stack Overflow MCP. Нерешённая проблема у всех — отравление базы. Идея «совет засчитывается после воспроизведения в контейнере» отложена, не отброшена.
- **Собственная криптография для секретов.** Отброшено.
- **Сжатие справочников в «нечитаемые токены».** Только после замера на реальных задачах.

Соседние проекты по памяти агентов (изучить, сохранять совместимость): agent-handover, AGENT_SYNC.md, mymem0ry, memcp, Memory Bank в Cline. Ни один не стал стандартом. AGENTS.md — стандарт для инструкций, но не для истории.

## 4. Открытые вопросы

- Зарегистрировать имя `why-isekai` в npm, PyPI, crates.io, Homebrew заранее (на 2026-11-03 свободно). Имя `isekai` занято в npm, PyPI и crates.io, поэтому установленная команда `isekai` может конфликтовать с чужим пакетом.
- crates.io и Homebrew/Scoop/winget: пока не сделаны (нужны отдельные репозитории tap/bucket и токены).
- Замер «с журналом и без»: одна серия задач для агентов, сравнить токены и число попыток. Нужен для продвижения стандарта.
- Адаптеры секретов: dotenvx, 1Password CLI, Vault, Infisical.

## 5. Стратегия распространения

- Сначала спецификация на одну страницу и простой сайт, потом инструмент.
- Затем пулл-реквесты с поддержкой в открытые среды агентов: OpenCode, Cline, Aider, Goose.
- Позже — Claude Code, Codex, Cursor и, возможно, передача спецификации в нейтральную организацию (Agentic AI Foundation при Linux Foundation, где уже MCP и AGENTS.md).
- Держать совместимость с форматами крупных игроков, чтобы IsekAI скорее вобрали, чем вытеснили.
