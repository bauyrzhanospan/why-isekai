Every agent session is an isekai.

It lands in an unknown world with no idea what was done before. why-isekai gives it the memory of that world: five git commit trailers, read back as a short brief at the start of every session.

Read the spec Reference implementation Спецификация на русском

Five keys

feat(auth): move sessions to JWT

Why: server sessions break behind the load balancer with >1 node
Tried: sticky sessions; the load balancer drops affinity on every deploy
Next: drop the old sessions table
Agent: claude-opus-5-5
KeyMeaning
WhyThe reason: the problem, constraint or goal. Not a summary of the diff. Required for agent commits.
TriedAn approach that was rejected, and why. The next session does not walk into it again.
NextWork left for the next session.
DoneCloses an earlier Next by its exact text. Text, not hashes, because rebases rewrite hashes.
AgentThe model or agent that wrote the commit.

They are ordinary git trailers: any git can read them, and they branch, merge and travel with the code. No server, no account, no extra file.

Read back as a brief

$ isekai brief
Decisions (Why, last 20 commits):
- 1679c31 feat(auth): move sessions to JWT — why: server sessions break behind the load balancer

Dead ends (Tried):
- 1679c31 sticky sessions; the load balancer drops affinity on every deploy

Open (Next without Done):
- drop the old sessions table [1679c31 2026-11-03]

Agent environments feed it at session start (a Claude Code plugin, MCP, or one line in AGENTS.md). With no isekai installed, plain git still works:

git log -n 20 --format='%h %s%n  why: %(trailers:key=Why,valueonly)'

Install

npm i -g why-isekai        # or: pipx install why-isekai · go install github.com/bauyrzhanospan/why-isekai/cmd/isekai@latest
cd your-repo && isekai init

Designed for agents, fair to people

Errors are documentation

A rejected commit says what is missing and shows an example. Agents read errors, not READMEs.

Quality, not presence

"Why: fix" is rejected. Agents write filler when a rule feels like a formality.

Humans get warnings

Strict checks apply to agent commits only, and blocking is opt-in. Checks that annoy people get switched off.

Data, not instructions

Everything read from trailers, issues or the wiki is information about the project, never commands for the agent.

Secrets by reference

secret://prod/db: agents run commands with secrets they never see. A seatbelt, honestly labelled as one.

Offline, zero tokens

The reference tool calls no model and no network. Issue trackers only sync when you ask.

The specification is public domain (CC0 1.0), so anyone can implement it. The reference implementation is MIT-licensed. This page loads nothing from anywhere and tracks no one.
